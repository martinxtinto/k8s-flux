# AGENTS.md

Flux GitOps config for homelab Kubernetes clusters, reconciled from `main`.
Manifests only: no application code, no build/test/lint/CI. `flux`, `kustomize`,
`kubectl`, and `helm` are available on PATH.

## Validating changes

There is no test suite. Validate YAML/kustomize rendering before committing:

- `kustomize build <dir>` (e.g. `kustomize build clusters/bee/production`)
- `flux build kustomization <name> --path clusters/bee/production` for one Flux Kustomization

## Layout and entrypoints

- `clusters/<cluster>/<env>/` — Flux entrypoint, bootstrapped per env with
  `flux bootstrap --path=clusters/<cluster>/<env>`.
- `clusters/<cluster>/<env>/infrastructure.yaml` / `apps.yaml` — the Flux dependency
  graph. `flux-system/` is generated by bootstrap and **must not be edited by hand**.
- `infrastructure/<cluster>/<unit>/base/` — canonical manifests. An env dir
  (`development/`, `production/`) exists only when it diverges; only `linstor-cluster` does.
- `apps/<cluster>/<app>/base/` — workloads (none for `bee` yet).
- `manifests/kubevirt/` — standalone kustomization pulling upstream KubeVirt/CDI/Multus
  releases with patches.

## Gotchas

- `bee/development` and `bee/production` `infrastructure.yaml` are near-duplicates. A new
  unit must be added to **both**; only the `linstor-cluster` path differs (`/development`
  vs `/production`).
- Every Flux Kustomization uses `prune: false`, plus `wait: true` with `dependsOn` for
  ordering. `dependsOn` links whole Flux Kustomizations; use HelmRelease `dependsOn` only
  for ordering inside a single unit.
- `oldbee` is archived and no longer reconciled (`clusters/oldbee/dev` has no config).
  Leave it alone except to recover manifests.
- Add a ServiceMonitor/PodMonitor next to the workload to be scraped — Prometheus uses
  empty selectors, so no labels are required.

## Conventions

- Helm: `HelmRepository` + `HelmRelease` (`helm.toolkit.fluxcd.io/v2`), both in the
  `flux-system` namespace, `targetNamespace` set, chart versions pinned.
- No plaintext secrets; everything goes through external-secrets backed by Bitwarden
  (`ClusterSecretStore: bitwarden-secrets-manager`). `external-secrets-store` becomes
  Ready only after the `bitwarden-access-token` Secret exists in the `external-secrets`
  namespace — a manual bootstrap step. Never commit credentials.
- Apps: `dependsOn` only what the app uses (`gateways` for HTTPRoutes, `linstor-cluster`
  for PVCs, `external-secrets-store` for ExternalSecrets). Attach HTTPRoutes to the
  `xtinto.com-https` listener of `bee-gateway`.

See `README.md` for the full dependency graphs and per-unit rationale.
